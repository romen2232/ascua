# ascua Plan 1 — Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A running backend and client where an invited user can sign up with mandatory TOTP, sign in on web, iOS and Android, and where the architecture rules and cross-user isolation are enforced by tests from the first commit.

**Architecture:** Django backend organised by bounded context (Screaming Architecture), each with `domain/`, `application/`, `infrastructure/`, `api/` layers. `domain` and `application` never import Django (import-linter). Tenant isolation lives in infrastructure: `TenantManager` refuses unscoped queries, and PostgreSQL row-level security (forced, fail-closed) sits underneath. Expo client (web + native) talks to a DRF API through a generated OpenAPI client.

**Tech Stack:** Python 3.13, uv, Django 5.2 LTS, DRF, drf-spectacular, djangorestframework-simplejwt, django-otp, argon2-cffi, django-axes, PostgreSQL 17, pytest + pytest-django + Hypothesis + factory-boy + time-machine, ruff, mypy (django-stubs), import-linter. Client: Expo (current stable SDK at scaffold time), TypeScript strict, expo-router, TanStack Query, openapi-typescript + openapi-fetch, i18next, expo-secure-store, Jest + React Native Testing Library.

**Spec:** `docs/superpowers/specs/2026-11-16-ascua-v1-design.md` (sections 3, 9, 10). Roadmap: `docs/roadmap.md`.

## Plan series (v1)

Each plan is written when the previous one is done, from the same design doc.

1. **Foundation** (this plan): scaffold, guardrails, isolation, identity, client auth.
2. Households and ledger: households, ownership shares, visibility, accounts, manual entry, net worth.
3. Importing: preview/undo, duplicates, transfer matching, generic CSV, then the six institutions one by one.
4. Spending: categories, rules, essential/discretionary, savings rate, recurring, sinking funds, shared-expense settlement.
5. Goals: simple goals, percentages, earmarks, projections, what-if; house goal (Andalusia pack); FIRE.
6. Safe to spend.
7. Market data: CNMV prices, ETF/stock provider, ECB FX, holdings valuation.
8. Demo deployment and sandbox lifecycle.
9. Ops polish: backups and restore, support access, GDPR export and deletion.

## Global Constraints

- Python 3.13; Django 5.2 LTS; PostgreSQL 17. Dependencies managed with `uv` from `backend/`.
- `backend/<context>/domain/` and `backend/<context>/application/` import no `django`, `rest_framework`, `celery`. Enforced by import-linter in CI.
- Contexts never import another context's `infrastructure` or `api`; cross-context calls go through `application`.
- Money is integer cents (`Money`), shares and percentages are integer basis points (`BasisPoints`), dates ISO 8601. No `float` in domain code.
- Every tenant table: `TenantManager` + RLS migration with `FORCE ROW LEVEL SECURITY`; the app connects as role `ascua_app` (no `BYPASSRLS`), migrations run as `ascua_owner`.
- Every API route is registered in `backend/tests/isolation/registry.py`; denied access returns 404, never 403.
- Admin users have no data privileges beyond their own; there is no RLS bypass for admins.
- Passwords hashed with Argon2id. TOTP is mandatory for every user.
- All user-facing strings in Spanish and English (Django gettext, i18next). No hard-coded copy in components.
- No telemetry, trackers, external fonts or CDNs.
- Tests first: every task writes its tests and sees them fail before implementing.
- Commits: Conventional Commits, no AI attribution or `Co-Authored-By` lines.

## Review Focus

1. **Email case and whitespace** — `Romen@Example.com ` and `romen@example.com` are the same user for invite, sign-up and sign-in; a duplicate account is impossible. Test in Task 6 (`test_email_normalises_case_and_whitespace`) and Task 8 (`test_accept_invitation_rejects_existing_email_in_other_case`).
2. **Code with no actor set** (management command, shell, future Celery task) querying a tenant table must see zero rows or raise, never all rows. Test in Task 3 (`test_rls_without_actor_returns_no_rows`, `test_tenant_manager_without_actor_raises`).
3. **Admin probing another user's data** — gets 404 exactly like any other user, and the response body doesn't reveal existence. Test in Task 5 (`test_admin_gets_404_on_other_users_item`).
4. **Invitation link reused or expired** — a second use or a use after 7 days fails with a clear, translated error and creates nothing. Test in Task 8 (`test_accept_used_invitation_returns_410`, `test_accept_expired_invitation_returns_410`).
5. **TOTP replay and clock drift** — the same code can't be used twice; a code from the previous or next 30-second step is accepted. Test in Task 9 (`test_totp_code_cannot_be_reused`, `test_totp_accepts_one_step_drift`).

### Task 8: Invitations and sign-up with TOTP enrolment

- Produces:
  - `invite_user(actor: Actor, email: Email, users, invitations, clock, token_factory) -> str` (raw token); only `actor.is_admin`, else `NotAllowed` (→ 404).
  - `accept_invitation(raw_token: str, display_name: str, password: str, locale: str, ...) -> TotpEnrolment` where `TotpEnrolment(user_id: UUID, provisioning_uri: str)`; rejects existing email (`EmailTaken` → 409).
